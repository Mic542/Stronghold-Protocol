# Act3 English game-text (M3 wiring) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** English UI shows full act3 (`act3autochess@V3_1`) game text by shipping a version overlay and wiring the client to load it (M3).

**Architecture:** Generate `data/versions/act3autochess-v3_1/i18n/en.json` from act3 Chinese tables + reuse of shared `data/i18n/en.json` + a Terra Archive dictionary. Extend the version content path so `showVersion` attaches that overlay (today it forces `overlay: null`). Keep version `cs` hash on `app+sim+data` only so translations do not invalidate room content identity.

**Tech Stack:** Node ESM, existing `shared/i18nData.js` (`buildRecordOverlay`, `applyFileOverlay`, `textHash2`), `public/js/content.js` / `data.js`, `server/versions.js`.

**Spec:** `docs/superpowers/specs/2026-11-20-act3-en-i18n-design.md`

## Global Constraints

- Full act3 game-text coverage attempt (operators, bonds, items, enemies, stages, bosses, garrisons, effects, tokens, choices, factions, backups, bands, config strings) — missing leaves stay Chinese.
- Terra Archive English is accepted as-is; no in-game “unofficial” banners.
- Do not hand-edit gameplay `data/versions/act3autochess-v3_1/*.json` tables; only add `i18n/en.json` and generator/dict tooling.
- Do not change default-version `cs` / golden identities.
- Commits only when the user explicitly asks.

- [ ] **Step 3: Implement `tools/build-version-i18n.mjs`**

Core algorithm:
1. `flattenReuse(baseEnJson)` — walk `baseEn.files` is wrong for zh keys; instead build reuse from `baseEn.names` plus a second pass: for every string leaf in act3 data, if `baseEn.names[zh]` use it; also invert by walking shared overlay is insufficient without zh. **Practical reuse:** load `data/i18n/en.json` `names`; additionally walk shared overlay files against **default** `data/*.json` Chinese to build `zh→en` map (same leaf paths). For act3-only strings, names/dict cover the rest.
2. Walk each act3 JSON file (skip `tuning.json` / `waves.json` if no player-facing strings — include all object tables that `build-i18n` uses: chess, bonds, items, bands, enemies, tokens, choices, config, backups, garrisons, effects, stages, bosses, factions).
3. For each string leaf: `en = reuseMap[zh] || dict[zh]`; if en and en !== zh and looks translated, keep leaf.
4. `buildRecordOverlay` per record; assemble `names` from record-level name keys.
5. CLI writes `--out` and `.cache/build-version-i18n-act3-en-report.json` with totals.
